- **Быстрее парсинг:** HTML парсится один раз вместо трёх

### Технические детали

**Миграции:**
- Autogenerate не работает для ENUM типов в PostgreSQL — требуется ручная доработка

- Добавлены volumes в `docker-compose.yml` для сохранения файлов миграций локально

**Оптимизация парсера:**
- Было: `BeautifulSoup` создавался 3 раза (в `parse()`, `_extract_product_name()`, `_extract_selected_variant()`)
- Стало: `BeautifulSoup` создаётся один раз и передаётся как параметр
- Добавлен `_SoupProxy` с коротким `__repr__` для чистых логов

**Обработка ошибок:**
- `ParserError`, `ValueError` → не ретраим (ошибки парсинга)
- `ConnectionError`, `TimeoutError` → ретраим через Celery autoretry
- `SoftTimeLimitExceeded` → помечаем как failed без retry

### Результат

### Технические детали

**Оптимизация удаления подписки:**
```python
# Было: 2 запроса
subscription = await repo.get(subscription_id)  # SELECT
if subscription.user_id != user_id: return False
await repo.delete(subscription)  # DELETE

# Стало: 1 запрос
deleted = await repo.delete_by_user(subscription_id, user_id)  # DELETE с WHERE
```

**Атомарность check_all_subscriptions:**
```python
# Было: обновление сразу после создания задачи
for subscription in subscriptions:
    parse_price.delay(subscription.id)
    await repo.mark_last_check_now(subscription.id)  # Если delay() упадёт — уже обновлено

# Стало: обновление только успешных задач
successful_ids = []
for subscription in subscriptions:
    parse_price.delay(subscription.id)
    successful_ids.append(subscription.id)

for sub_id in successful_ids:
    await repo.mark_last_check_now(sub_id)
```

## Задача 22. Rate Limiting и защита от блокировок

Статус: ⚠️ Осознанно упрощена

### Описание

Попытка внедрить сложные механизмы защиты от блокировок Ozon (stealth-плагины, глобальный rate limiter через Redis, retry с exponential backoff) привела к обратному эффекту — Ozon начал чаще показывать капчу.

### Попытки (откачены)
* [ ] `playwright-stealth` плагины — провоцировали детектирование
* [ ] Глобальный rate limiter через Redis — не решал проблему fingerprint
* [ ] Блокировка ресурсов через `page.route()` — ломала рендеринг
* [ ] Рандомизация User-Agent — не влияла на антибот

### Оставлено (работает стабильно)
* [x] Естественные `_human_delay` (0.2-1.5 сек) для имитации человеческого поведения
* [x] `--disable-blink-features=AutomationControlled` в Chromium
* [x] `Object.defineProperty(navigator, 'webdriver', {get: () => undefined})`
* [x] Встроенный Celery `autoretry` для сетевых ошибок

### Вывод

Для headless Chromium без прокси **естественные задержки работают лучше**, чем агрессивные stealth-плагины. Полноценная защита от блокировок требует **пула резидентных/мобильных прокси**, что является инфраструктурной задачей, а не задачей кода парсера.

### Рекомендация на будущее

При росте числа подписок до 100+ и появлении массовых блокировок:
1. Подключить пул резидентных прокси через существующий `ProxyService`
2. Настроить ротацию прокси на уровне `MarketplaceHttpClient`
3. Не возвращаться к stealth-плагинам — они только усугубляют проблему
